# NAPS + ResCNN — проект для VS Code

Код вашего `NAPS_Calo_From_Scratch_lastlast(3).ipynb` перенесён в обычные Python-файлы.
Готовые веса `NAPS_Calo_ResCNN_weights(2).pt` включены. Обычный запуск использует
эти веса, создаёт CSV для новых событий и сохраняет графики. Исходные обучающие
словари для этого не нужны.

## Быстрый запуск на Windows

1. Полностью распакуйте архив. Не запускайте файлы внутри окна ZIP.
2. Если Python ещё не установлен, установите **Python 3.12 или 3.13, 64 bit**
   с [python.org](https://www.python.org/downloads/). В установщике включите
   **Add Python to PATH**. Также поддерживается Python 3.11.
3. Откройте распакованную папку `NAPS_VSCode` и дважды нажмите **START_WINDOWS.bat**.

Скрипт сам создаст `.venv`, установит зависимости и запустит `main.py`.
При первой установке нужен интернет; установка PyTorch может занять несколько минут.
Последующие запуски используют уже установленную среду. Видеокарта и CUDA
для стандартного запуска не требуются. Команды активации PowerShell не нужны.

После сообщения `Готово` откройте `outputs`:

- `submission_session_demo.csv` — предсказания для 32 демонстрационных событий;
- `test_metrics.csv`, `classifier_metrics.csv`, `audit_summary.csv` — сохранённые
  тестовые результаты из приложенных весов;
- `thresholds.csv` — активные пороги NAPS;
- `figures/coverage_power.png`, `figures/training.png` — графики из сохранённых результатов;
- `run_metadata.json` — устройство, версии, источник метрик и параметры запуска.

**Демонстрационные события искусственные.** Они проверяют, что проект запускается
и создаёт CSV. Качество модели на них не оценивается. При стандартном запуске
новый test не выполняется: это явно указано в консоли и столбце `evaluation_source`.

## Запуск непосредственно из VS Code

1. **File → Open Folder**: выберите именно папку `NAPS_VSCode`, где лежит `main.py`.
2. Установите предложенные расширения **Python** и **Python Debugger** от Microsoft.
3. Если ещё не запускали `START_WINDOWS.bat`, сначала выберите **Terminal →
   Run Task → NAPS: установить зависимости**. Дождитесь завершения установки `.venv`.
4. Откройте **Run and Debug**, выберите **NAPS: запуск с готовыми весами** и нажмите **F5**.

Перед запуском задача VS Code установит зависимости. В Windows она автоматически
выбирает Python Launcher `py` или команду `python`, если Launcher отсутствует.

Если VS Code предлагает выбрать интерпретатор, нажмите **Ctrl+Shift+P →
Python: Select Interpreter → Enter interpreter path** и укажите
`.venv\Scripts\python.exe`. Конфигурации F5 уже используют этот путь напрямую.

Также доступны задачи **Terminal → Run Task → NAPS: ...**.
**Ctrl+Shift+B** запускает модель в подготовленной среде.

## Свои события → CSV

Положите свои файлы `session*.npz` в `data/sessions`, затем запустите проект снова.
Для каждого файла появится отдельный `outputs/submission_<имя>.csv`.
Демонстрационный файл можно удалить, когда он больше не нужен.

Ожидаемый формат NPZ:

```python
import numpy as np

# X: реальные энергии, float32, форма (N, 4, 8, 8)
# event_id: необязательный одномерный массив длины N
np.savez_compressed("data/sessions/session_my_events.npz", X=X, event_id=event_id)
```

Все энергии должны быть конечными и неотрицательными. Вместо ключа `X` принимается
`values`. Поддерживаются одно событие `(4, 8, 8)` и форма `(K, R, 4, 8, 8)`:
последняя разворачивается сначала по K, затем по R. `event_id` должен соответствовать
этому порядку. Если идентификаторов нет, назначаются числа `0, ..., N-1`.

Файл с произвольным именем или из другой папки можно указать явно:

```powershell
.\.venv\Scripts\python.exe main.py --session "D:\my_data\events.npz" --device cpu
```

Можно повторить `--session` несколько раз. При явном `--session` используются
только перечисленные файлы. Относительные пути всегда отсчитываются от папки проекта.
Текущая рабочая папка терминала не влияет на встроенные пути.

CSV сохраняет формат ноутбука:

| Колонка | Значение |
| --- | --- |
| `event_id` | Идентификатор события |
| `H_0.05` | Множество гипотез для α = 0.05 |
| `H_0.10` | Множество гипотез для α = 0.10 |
| `H_0.20` | Множество гипотез для α = 0.20 |

Коды множеств: **0 = пустое**, **1 = {0}**, **2 = {1}**, **3 = {0, 1}**.
Вероятность класса 1 доступна через `ResCNNNAPSPredictor.predict` и не добавляется
в submission CSV, чтобы сохранить исходный формат.

## Три режима

| Режим | Что делает | Нужны ли `calo_dictionary*.npz`? |
| --- | --- | --- |
| `pretrained` | Загружает приложенные веса, использует сохранённые пороги, создаёт CSV | Нет |
| `pretrained --evaluate-data` | Заново оценивает сеть и NAPS на сохранённой test-части | Да, все исходные файлы этих весов |
| `recalibrate` | Сохраняет сеть и нормализацию, заново строит W и пороги с γ = 0 | Да, все исходные файлы этих весов |
| `train` | Обучает новую ResCNN с нуля, затем строит W, калибрует NAPS и оценивает test | Да; допускаются другие данные правильного формата |

Веса в архиве имеют **γ = 0.005** и α = 0.05, 0.10, 0.20.
В режиме `pretrained` они используются без перекалибровки.
В `train` и `recalibrate` новые пороги соответствуют **γ = 0**,
как в исходном ноутбуке для новой калибровки. Гарантия на непрерывном nuisance-домене
в checkpoint не сертифицирована (`continuum_certified=False`); сохранённая область
проверки покрытия — усреднение по nuisance-бинам при дизайне симуляций.

Этот перенос сам по себе не меняет архитектуру или качество приложенной модели.
Её предсказания проверены на совпадение с исходными ячейками ноутбука.

### Повторная оценка на ваших исходных данных

Скопируйте все три исходных NPZ в `data/simulations`. Для вложенных весов это:

- `calo_dictionary_300000(3).npz`;
- `calo_dictionary_50000(4).npz`;
- `calo_dictionary_649800(3).npz`.

Файлы определяются по содержимому, поэтому имя можно поменять на любое
`calo_dictionary*.npz`. Сохранённые индексы требуют именно исходного содержимого.
Эти большие обучающие файлы **не включены в архив**. Их отсутствие не мешает
запуску `pretrained` и обработке новых событий.

```powershell
.\.venv\Scripts\python.exe main.py --mode pretrained --evaluate-data --device cpu --output-dir outputs/evaluation
```

Если файлы лежат в другой папке, добавьте `--data-dir "D:\calo_data"`.
Перед повторной оценкой проверяются SHA-256 и независимость частей данных.

### Перекалибровка и обучение

CatBoost нужен только для этих режимов. Установщик добавляет его автоматически
при передаче `--mode train` или `--mode recalibrate`:

```powershell
python bootstrap.py --mode recalibrate --device cpu --output-dir outputs/recalibrate
python bootstrap.py --mode train --device cpu --output-dir outputs/train
```

При запуске через F5 выберите конфигурацию обучения: её задача установит CatBoost.
Для ручной подготовки всех библиотек:

```powershell
python bootstrap.py --install-only --with-training
```

Для `train` NPZ должны содержать `keys` формы `(K, 3)` со столбцами `[y, E, g]`
и `values` формы `(K, R, 4, 8, 8)`. Требуются оба класса на каждом `(E,g)`,
одинаковое число повторов классов, E ∈ [1,100], g ∈ [0.7,1.3].
Бюджет — не более 1 000 000 физических событий. Повторы одного `(E,g)` остаются
в одной части данных. Нормализация рассчитывается только на train.

Обучение сохраняет `outputs/train/NAPS_Calo_ResCNN_gamma0.pt` с новыми порогами,
индексами и тестовыми метриками. Исходные веса в `weights` остаются прежними.
Для последующего вывода с новой моделью:

```powershell
.\.venv\Scripts\python.exe main.py --weights outputs/train/NAPS_Calo_ResCNN_gamma0.pt --output-dir outputs/new_model --device cpu
```

Уменьшить длительность пробного обучения можно через `--max-epochs 2 --w-iterations 20`.
Это проверка работоспособности, а не настройка для максимального качества.
По умолчанию остаются 40 эпох, patience 10 и до 800 итераций W.
`--batch-size` управляет пакетами inference; размер пакета обучения берётся из
сохранённого `config` и равен 512.

При загрузке словарей создаётся `.cache/naps/raw.npy`. Для 999 800 событий это
приблизительно 1.02 ГБ, дополнительно к исходным NPZ.

`bootstrap.py` — только установка и запуск; `main.py` — точка входа.

## Linux и уже установленная среда

```bash
bash start.sh
# или
python3 bootstrap.py --mode pretrained --device cpu
# после установки
./.venv/bin/python main.py --device cpu
```

Если зависимости уже есть в вашем выбранном интерпретаторе, можно сразу выполнить
`python main.py`. Установщик создаёт отдельную среду и не меняет глобальные библиотеки.

Для GPU установите подходящий PyTorch по [официальной инструкции](https://pytorch.org/get-started/locally/)
в `.venv`, затем запустите `python bootstrap.py --keep-torch --install-only`,
чтобы последующие запуски сохраняли ваш профиль PyTorch. Запускайте `main.py --device cuda`.
Комплект проверен на CPU; GPU-путь сохранён из ноутбука.

## Проверки и ошибки

```powershell
.\.venv\Scripts\python.exe main.py --check --device cpu
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tests/smoke_training.py
.\.venv\Scripts\python.exe main.py --help
```

- `Нет calo_dictionary*.npz`: выбран режим с данными. Положите NPZ в
  `data/simulations` или используйте обычный `pretrained` без `--evaluate-data`.
- `Не установлены библиотеки`: запустите `START_WINDOWS.bat` или `bootstrap.py`.
- `CUDA недоступна`: используйте `--device cpu`.
- `Нет файла весов`: распакуйте весь архив вместе с папкой `weights`.
- Для полного сообщения об ошибке добавьте `--debug`.

Дополнительные проверки переноса перечислены в `VALIDATION.md`.
`smoke_training.py` требует CatBoost и выполняет короткие проверки на временных
искусственных данных; результаты этих проверок не являются метриками вашей модели.
